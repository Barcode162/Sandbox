STATUS: DONE
Engineer discipline: rendering · Mission: M-0001 · Round: build

## What I built
The scenes' shared renderers now exist under `site/js/components/`:
- **`svg.js`:** `el()` creates elements in the right namespace. `setAttrs()` and `setStyles()` skip a write when the value equals the one last written to that node, using a per-node WeakMap cache, so a recreated node starts empty.
- **`bands-dom.js`:** seven flat divs. Each call writes only `transform` and `opacity`. Edges are snapped to device pixels, and the group is isolated so that screen-blended bands keep their exact token colours over Scene 5's ink.
- **`dotgrid-svg.js`:** vertex and fill subsets × ink and white tones, drawn as four pattern fills on four rects, with every pattern id prefixed by `idPrefix`.
- **`white-point.js`:** a disc of at most 6 px (r is clamped to 3) with a 1 px ring, hosted in SVG or HTML.

There is also a component gallery (`dev/components/`, 9 fixtures plus a solo full-window mode) and a 24-test dev e2e.

## Self-review against the quality bar
I reviewed the diff and fixed these:
1. **Invisible HTML-hosted points.** A zero-size `<svg>` disables rendering under the SVG spec, so every HTML-hosted white point was invisible. The host is now 1×1 with `overflow: visible`. The pixel test caught this.
2. **Wrong measure in the white-point test.** A threshold pixel count reads a 3 px disc on an integer centre as 2 px (the edge pixels are half covered). It now uses coverage width.
3. **Test sampled too late.** The MutationObserver test read attributes asynchronously. It now uses `takeRecords()` after each call.
4. **Dead code and typing.** I removed dead code from the transform-only test. The test page uses the `__gallery.geometry` export instead of `import('/js/...')` so it typechecks.
5. **Gallery edge.** The wall-ground panels had no visible edge, so they now have an outline outside the box, which leaves the art pixels untouched.

Two design decisions:
- **Group isolation.** `isolation: isolate` on the band group is deliberate. Without it, screened bands would blend with Scene 5's `--ink` (#0C0F1A, not black) and drift off their token colours, which would break the 4→5 identity seam.
- **Re-snapping.** The component snaps edges again with `geometry.snap`. Snapping is idempotent for WO-002's already-snapped rects, and it guarantees #4 for scene-computed rects such as Scene 5's moving beams.

## Known gaps, risks, follow-ups
- **Evidence overwritten by the mutant run.** During my mutant run the Gallery test overwrote the evidence PNGs with broken frames. I then regenerated them from the clean build, and the current files are clean. WO-023's `verify:mutants` should point `EVIDENCE_DIR` at a temporary directory so it never overwrites real evidence.
- **Unit-box scaling assumption.** Band boxes are U×V scaled down by `transform`. If a scene puts `will-change: transform` on a band ancestor, the raster stays vector-painted in Chromium, but I did not test that combination.
- **Grid-mode panels at fractional DPR.** The gallery's grid panels can sit on half device pixels at DPR 1.5, because the text above them has fractional heights. The pixel scans therefore run in solo mode at (0, 0).
- **Scene usage not yet proven.** The components are proven in isolation. Each scene WO still has to use them, and WO-013's E-S seams will prove that in situ.
